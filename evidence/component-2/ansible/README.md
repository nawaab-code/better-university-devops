# Component 2: Ansible evidence

Every `.log` is raw, unedited output (ANSI colours kept, `ANSIBLE_FORCE_COLOR=1`) captured with `tee`
from `ansible/` against the `bu-ansible-target` container. Each `.png` is a `freeze` render of the log
(or source file) with the same number; PNGs were only scaled down to 2000 px wide.

| File | What it proves |
|---|---|
| `00-ansible-version.log/.png` | Ansible core 2.21.6, config file `ansible/ansible.cfg` is picked up |
| `01-ping.log/.png` | `ansible -m ping` reaches the target over SSH (key auth, host 127.0.0.1:2222) |
| `02-syntax-check.log/.png` | `ansible-playbook --syntax-check` passes |
| `03-first-run.log/.png` | First run on a fresh host: `ok=13 changed=9`; JDK installed, user and dir created, JAR copied, unit written, handlers fire (`daemon reload`, `restart bu-campus-api`), service enabled, `/health` returns 200 with version 1.0.0 |
| `04-second-run-idempotent.log/.png` | Second run: `ok=11 changed=0`, no `RUNNING HANDLER` lines, so the handler did **not** fire (idempotent) |
| `05-new-version-run.log/.png` | After `./gradlew build -PappVersion=1.1.0` and `-e app_version=1.1.0`: JAR, env file and unit change (`changed=4`), handlers fire, `/health` now reports 1.1.0 |
| `06-third-run-idempotent-after-upgrade.log/.png` | Run again with 1.1.0: `changed=0`, no handler, so the upgrade is stable |
| `07-systemctl-status.log/.png` | Inside the target: `systemctl status bu-campus-api` is `active (running)` and `enabled`, PID 1 is `systemd`, rendered unit file and env file |
| `08-curl-from-mac.log/.png` | From the Mac through published port 18081: `/health` 200, GET and POST `/api/v1/announcements` |
| `09-role-tree.txt/.png` | Role structure generated by `ansible-galaxy init roles/bu_campus_api` |
| `10-playbook.png` | `playbook.yml` (variables `app_port`, `app_version`, role call) |
| `11-handlers.png` | `handlers/main.yml` (`daemon reload`, `restart bu-campus-api`) |
| `12-systemd-unit-template.png` | `templates/bu-campus-api.service.j2` |
| `13-tasks.png` | `tasks/main.yml` with the `notify:` lines |
| `14-defaults.png` | `defaults/main.yml` (`app_port`, `app_version`, `app_user`, `app_dir`, `jar_src`) |
| `15-inventory.png` | `inventory.ini` (group `campus_api`) |
| `16-target-dockerfile.png` | `ansible/target-host/Dockerfile` (Ubuntu 24.04, systemd, sshd) |

Note: in the logs the `daemon reload` handler shows `ok`, not `changed`. That is how `systemd_service`
reports `daemon_reload`; the line `RUNNING HANDLER [... daemon reload]` is what shows it ran.
The POST in `08` adds an announcement to the service's in-memory data, which resets on restart.
